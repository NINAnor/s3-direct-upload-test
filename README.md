# S3 Direct Upload Demo

A Python web application that demonstrates direct browser-to-S3 file uploads using presigned URLs. Built with FastAPI, Uppy, and RustFS (S3-compatible storage).

## Features

- **Direct Browser-to-S3 Uploads**: Files upload directly from browser to S3 without going through the application server
- **Presigned URLs**: Secure, time-limited upload URLs generated by the backend
- **Beautiful UI**: Professional upload interface powered by Uppy
- **Multiple File Upload**: Upload multiple files simultaneously
- **Large File Support**: Automatic multipart uploads for files larger than 100MB
- **Progress Tracking**: Real-time upload progress with pause/resume capability
- **Automatic Retry**: Failed uploads are automatically retried
- **S3-Compatible Storage**: Uses RustFS (2.3x faster than MinIO)
- **Modern Python Stack**: FastAPI + uv for fast dependency management

## Quick Start

### 1. Clone or navigate to the project directory

```bash
cd test-direct-upload
```

### 2. Start the services

```bash
docker compose up --build
```

This will start two services:
- **FastAPI Web App**: http://localhost:8000
- **RustFS Console**: http://localhost:9001 (credentials: minioadmin/minioadmin)

### 3. Open the application

Navigate to http://localhost:8000 in your browser.

### 4. Upload files

- Drag and drop files or click to browse
- Select multiple files (up to 20)
- Click "Upload" to start
- Watch the progress bars

### 5. View uploaded files

Access the RustFS console at http://localhost:9001 to see uploaded files in the `uploads` bucket.
- Default credentials: `rustfsadmin` / `rustfsadmin`

## Configuration

Edit `.env` file to configure:

```env
# S3 Configuration
S3_ENDPOINT=http://rustfs:9000          # Internal endpoint
S3_PUBLIC_ENDPOINT=http://localhost:9000 # Browser-accessible endpoint
S3_ACCESS_KEY=minioadmin
S3_SECRET_KEY=minioadmin
S3_BUCKET_NAME=uploads
S3_REGION=us-east-1

# Presigned URL expiration (seconds)
PRESIGNED_URL_EXPIRATION=3600

# Debug mode
DEBUG=true
```

## API Endpoints

### Application Endpoints

- `GET /` - Upload page
- `GET /health` - Health check
- `GET /docs` - API documentation (Swagger UI)

### S3 Signing Endpoints (for Uppy)

- `POST /s3/params` - Generate presigned URL for single file upload
- `POST /s3/multipart` - Create multipart upload
- `GET /s3/multipart/{uploadId}` - List uploaded parts
- `GET /s3/multipart/{uploadId}/{partNumber}` - Sign individual part
- `POST /s3/multipart/{uploadId}/complete` - Complete multipart upload
- `DELETE /s3/multipart/{uploadId}` - Abort multipart upload

## How It Works

### Single File Upload (<100MB)

1. User selects file in browser
2. Uppy requests presigned URL from FastAPI (`POST /s3/params`)
3. FastAPI generates presigned PUT URL using boto3
4. Uppy uploads file directly to RustFS using presigned URL
5. Browser receives success response

### Large File Upload (>100MB)

1. User selects large file
2. Uppy creates multipart upload (`POST /s3/multipart`)
3. File is split into 5MB chunks
4. Each chunk is signed (`GET /s3/multipart/{uploadId}/{partNumber}`)
5. Chunks upload in parallel directly to RustFS
6. Uppy completes multipart upload (`POST /s3/multipart/{uploadId}/complete`)
7. RustFS combines chunks into single object

## Troubleshooting

### RustFS not starting

```bash
# Check RustFS logs
docker compose logs rustfs

# Restart RustFS
docker compose restart rustfs
```

### CORS Behavior

**Important Note**: RustFS does not yet implement the S3 `PutBucketCors` API. You may see an error in the logs:
```
ERROR - Error setting CORS configuration: An error occurred (NotImplemented) when calling the PutBucketCors operation
```

This is **expected and does not affect functionality**. RustFS handles CORS at the HTTP server level (configured via `RUSTFS_CONSOLE_CORS_ALLOWED_ORIGINS=*` in docker-compose.yml), so browser uploads work correctly without the S3 API call.

For production:
1. Update CORS origins in `app/main.py` 
2. Update `RUSTFS_CONSOLE_CORS_ALLOWED_ORIGINS` in docker-compose.yml to specific origins

### Files not uploading

1. Check browser console for errors
2. Check FastAPI logs: `docker compose logs web`
3. Verify RustFS is healthy: `docker compose ps`
4. Check RustFS console at http://localhost:9001

### Port conflicts

If ports 8000, 9000, or 9001 are in use:
1. Edit `docker-compose.yml` to use different ports
2. Update `.env` with new `S3_PUBLIC_ENDPOINT`

## Security Considerations

### For Production

1. **CORS**: Restrict to specific origins
   ```python
   # In app/main.py
   allow_origins=["https://yourdomain.com"]
   ```

2. **Presigned URL Expiration**: Reduce expiration time
   ```env
   PRESIGNED_URL_EXPIRATION=300  # 5 minutes
   ```

3. **File Size Limits**: Configure in Uppy
   ```javascript
   restrictions: {
       maxFileSize: 100 * 1024 * 1024, // 100MB
   }
   ```

4. **File Type Restrictions**: Limit allowed file types
   ```javascript
   restrictions: {
       allowedFileTypes: ['.jpg', '.png', '.pdf']
   }
   ```

5. **Authentication**: Add user authentication before generating presigned URLs

6. **HTTPS**: Use HTTPS in production

7. **Secrets**: Use proper secret management (not .env files)
